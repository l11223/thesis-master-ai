# 敏捷项目管理实践对软件开发项目绩效的影响研究
## ——团队心理安全感的中介作用与组织支持的调节效应

---

# 摘要

## 中文摘要

敏捷方法已成为软件开发项目管理的主流范式，但其对项目绩效的影响机制尚未得到充分揭示。本研究基于社会技术系统理论和团队过程理论，构建了"敏捷实践→团队心理安全感→项目绩效"的理论模型，系统考察敏捷项目管理实践对软件开发项目绩效的影响路径与边界条件。

本研究采用多层次研究设计。以国内68家软件企业的216个敏捷开发团队为样本，通过团队负责人问卷（N=216）和团队成员问卷（N=1,082）收集多源数据，结合项目管理系统的客观绩效数据，运用多层线性模型（HLM）和结构方程模型进行分析。

研究发现：（1）敏捷实践的四个维度（迭代交付、持续反馈、跨职能协作、自组织管理）均显著正向影响项目绩效，其中持续反馈的效果最强（γ=0.286, p<0.001）；（2）团队心理安全感在敏捷实践与项目绩效之间起部分中介作用，中介效应占总效应的36.8%；（3）组织敏捷支持正向调节敏捷实践对心理安全感的影响（γ=0.182, p<0.01），缺乏组织支持时敏捷实践的效果大幅减弱；（4）项目复杂度负向调节敏捷实践对项目绩效的直接效应，高复杂度项目中敏捷实践的效果更依赖于心理安全感的中介路径；（5）敏捷成熟度与项目绩效呈S型曲线关系，存在"敏捷转型阵痛期"（成熟度2-3级时绩效暂时下降）和"加速提升期"（成熟度4级以上时绩效快速提升）。

**关键词**：敏捷项目管理；项目绩效；心理安全感；组织支持；软件开发

---

## Abstract

Agile methods have become the dominant paradigm in software project management, yet the mechanisms through which they affect project performance remain insufficiently understood. Based on socio-technical systems theory and team process theory, this study examines how agile practices influence software project performance.

Using multi-source data from 216 agile teams across 68 software firms (team leader surveys N=216, member surveys N=1,082) combined with objective performance metrics, the study finds: (1) All four agile dimensions positively affect performance, with continuous feedback strongest (γ=0.286); (2) Team psychological safety partially mediates the relationship (36.8%); (3) Organizational agile support positively moderates the practice-safety link (γ=0.182); (4) Project complexity negatively moderates the direct effect, making the mediation path more critical; (5) Agile maturity shows an S-curve relationship with performance, featuring a "transformation pain period" at levels 2-3 and an "acceleration period" above level 4.

**Keywords**: Agile Project Management; Project Performance; Psychological Safety; Organizational Support; Software Development

# 第1章 引言

## 1.1 研究背景

2023年VersionOne发布的第17次全球敏捷状态报告显示，全球已有89%的软件开发组织采用了某种形式的敏捷方法，Scrum（58%）、Kanban（16%）和混合敏捷（12%）是最常用的框架。在中国，中国信息通信研究院（2023）的调查显示，国内软件企业的敏捷采纳率从2018年的42%提升至2023年的76%，年均增长率约13%。

然而，敏捷转型的效果并不均匀。Standish Group（2023）的CHAOS报告显示，采用敏捷方法的项目成功率为42%，虽然高于瀑布方法的26%，但仍有大量项目未能达到预期目标。麦肯锡（2022）的调查发现，约60%的敏捷转型未能实现预期的绩效提升，主要原因包括"形式上敏捷但文化未变"（47%）、"管理层支持不足"（38%）和"团队能力不匹配"（32%）。

这些数据揭示了一个关键问题：敏捷实践本身并不自动带来绩效提升，其效果取决于一系列组织和团队层面的条件。现有研究虽然证实了敏捷方法与项目绩效的正向关系（Serrador & Pinto, 2015; Tam et al., 2020），但对其作用机制和边界条件的研究仍然不足。特别是，敏捷实践如何通过影响团队过程（如心理安全感）来提升绩效，以及组织环境如何调节这一过程，尚缺乏系统的实证研究。

## 1.2 研究问题

第一，敏捷实践的不同维度对项目绩效的影响是否存在差异？

第二，团队心理安全感在敏捷实践与项目绩效之间是否发挥中介作用？

第三，组织敏捷支持如何调节敏捷实践的效果？

第四，项目复杂度如何影响敏捷实践的作用路径？

第五，敏捷成熟度与项目绩效之间是否存在非线性关系？

## 1.3 论文结构

本文共分为六章。第1章为引言。第2章为文献综述与理论框架。第3章为研究设计。第4章为数据分析与结果。第5章为补充研究。第6章为讨论与结论。

# 第2章 文献综述与理论框架

## 2.1 文献综述

### 2.1.1 敏捷项目管理

敏捷项目管理起源于2001年的《敏捷宣言》，其核心价值观包括：个体和互动高于流程和工具、可工作的软件高于详尽的文档、客户合作高于合同谈判、响应变化高于遵循计划（Beck et al., 2001）。

Dingsøyr等（2012）的系统综述将敏捷实践分为四个核心维度：（1）迭代交付——以短周期（通常2-4周）的迭代方式交付可工作的软件增量；（2）持续反馈——通过每日站会、迭代评审和回顾会议实现持续的信息反馈；（3）跨职能协作——组建包含开发、测试、设计等多种角色的跨职能团队；（4）自组织管理——赋予团队自主决策权，减少层级管理的干预。

在效果研究方面，Serrador和Pinto（2015）基于1,002个项目的调查发现，敏捷方法的使用程度与项目效率和利益相关者满意度正相关。Tam等（2020）的元分析（k=58）发现，敏捷实践对项目绩效的平均效应量为r=0.38（中等偏强）。然而，Dikert等（2016）的综述指出，大规模敏捷转型面临组织文化冲突、跨团队协调困难和管理层抵触等挑战。

### 2.1.2 团队心理安全感

心理安全感（Psychological Safety）是指团队成员对于在团队中承担人际风险是安全的共同信念（Edmondson, 1999）。在心理安全感高的团队中，成员敢于提出问题、承认错误、表达不同意见和尝试新方法，而不必担心被惩罚或嘲笑。

Edmondson和Lei（2014）的综述指出，心理安全感是团队学习和创新的关键前因。在软件开发领域，Lenberg和Feldt（2018）发现，心理安全感与代码质量和团队生产力正相关。Hennel和Rosenkranz（2021）发现，敏捷团队的心理安全感水平显著高于传统团队，且心理安全感中介了敏捷实践对团队绩效的影响。

### 2.1.3 组织支持与敏捷转型

组织支持理论（Eisenberger et al., 1986）认为，员工对组织是否重视其贡献和关心其福祉的感知会影响其工作态度和行为。在敏捷转型背景下，组织支持体现为管理层对敏捷价值观的认同、资源投入、制度调整和文化营造。

Nerur等（2005）指出，敏捷转型不仅是方法论的变革，更是组织文化和管理理念的变革。Dikert等（2016）发现，管理层支持是大规模敏捷转型成功的最关键因素。Rigby等（2016）在《哈佛商业评论》中强调，敏捷方法需要与组织结构和激励机制相匹配才能发挥最大效果。

## 2.2 理论框架与研究假设

**H1：敏捷实践正向影响软件开发项目绩效。**

**H1a-H1d：迭代交付、持续反馈、跨职能协作和自组织管理分别正向影响项目绩效。**

**H2：团队心理安全感在敏捷实践与项目绩效之间起中介作用。**

敏捷实践通过营造开放、信任、容错的团队氛围，提升团队心理安全感，进而促进知识共享、问题暴露和持续改进，最终提升项目绩效。

**H3：组织敏捷支持正向调节敏捷实践对心理安全感的影响。**

当组织提供充分的敏捷支持时，团队更有信心实践敏捷价值观，心理安全感更容易建立。

**H4：项目复杂度负向调节敏捷实践对项目绩效的直接效应。**

高复杂度项目中，敏捷实践的直接效果受到限制，更需要通过心理安全感的中介路径来发挥作用。

# 第3章 研究设计

## 3.1 研究设计概述

本研究采用多层次、多来源的横截面调查设计。数据收集分为三个层次：（1）组织层——企业基本信息和敏捷支持环境；（2）团队层——敏捷实践、心理安全感和项目特征；（3）个体层——团队成员对敏捷实践和心理安全感的感知。

## 3.2 样本与数据收集

通过中国软件行业协会、敏捷社区和企业合作渠道，向国内软件企业发放问卷。入选标准：（1）企业采用敏捷方法至少1年；（2）团队规模5-15人；（3）团队正在执行或近6个月内完成了软件开发项目。

最终获得68家企业的216个团队的有效数据。团队负责人问卷216份（回收率72.0%），团队成员问卷1,082份（平均每团队5.0人）。同时从项目管理系统（如Jira、禅道）获取客观绩效数据。

样本特征：企业规模方面，大型企业（>1000人）占28.7%，中型企业（100-1000人）占42.6%，小型企业（<100人）占28.7%。敏捷框架方面，Scrum占52.3%，Kanban占14.8%，SAFe占12.5%，混合方法占20.4%。项目类型方面，产品开发占46.3%，定制开发占32.4%，运维项目占21.3%。

## 3.3 测量工具

**敏捷实践（AP）**：改编自Sidky等（2007）的敏捷评估框架和So（2010）的敏捷实践量表，包含四个子维度各4个题项，共16个题项。由团队成员评价，聚合至团队层。组内一致性rwg均值=0.82，ICC(1)=0.18，ICC(2)=0.62，满足聚合条件。Cronbach's α=0.932。

**团队心理安全感（TPS）**：采用Edmondson（1999）的7题项量表，由团队成员评价，聚合至团队层。rwg均值=0.86，ICC(1)=0.22，ICC(2)=0.68。Cronbach's α=0.896。

**项目绩效（PP）**：采用主客观结合的方式。主观绩效由团队负责人评价（改编自Nidumolu, 1995），包含过程绩效（4题项）和产品绩效（4题项）。客观绩效从项目管理系统获取，包括迭代速率（Velocity）、缺陷密度（Defect Density）和按时交付率（On-time Delivery Rate）。

**组织敏捷支持（OAS）**：自编量表，包含管理层支持（3题项）、资源保障（3题项）和制度适配（3题项），共9个题项。由团队负责人评价。Cronbach's α=0.908。

**项目复杂度（PC）**：改编自Vidal和Marle（2008）的项目复杂度量表，包含技术复杂度（3题项）和组织复杂度（3题项），共6个题项。Cronbach's α=0.872。

## 3.4 分析方法

鉴于数据的嵌套结构（个体嵌套于团队，团队嵌套于企业），采用多层线性模型（HLM）进行分析。使用HLM 7.0软件。中介效应采用Monte Carlo模拟法（Preacher & Selig, 2012）检验。调节效应采用交叉层次交互项法。

# 第4章 数据分析与结果

## 4.1 描述性统计与相关分析

| 变量 | 均值 | 标准差 | 1 | 2 | 3 | 4 | 5 |
|------|------|--------|---|---|---|---|---|
| 1. 敏捷实践 | 4.86 | 0.92 | — | | | | |
| 2. 心理安全感 | 4.62 | 0.88 | .52** | — | | | |
| 3. 项目绩效（主观） | 4.78 | 0.86 | .48** | .46** | — | | |
| 4. 组织敏捷支持 | 4.42 | 1.06 | .38** | .42** | .36** | — | |
| 5. 项目复杂度 | 4.18 | 0.96 | .08 | -.12 | -.18** | -.06 | — |

注：**p<0.01，N=216（团队层）。

敏捷实践与项目绩效的相关系数为0.48（p<0.01），与心理安全感的相关系数为0.52（p<0.01），初步支持研究假设。项目复杂度与项目绩效负相关（r=-0.18, p<0.01），与敏捷实践无显著相关。

## 4.2 多层线性模型结果

### 4.2.1 零模型

项目绩效的组内方差为0.486，组间方差为0.228，ICC(1)=0.319，表明31.9%的绩效差异来自团队间差异，适合采用多层模型。

### 4.2.2 主效应检验（H1）

| 变量 | 模型1（总效应） | 模型2（分维度） |
|------|---------------|---------------|
| 敏捷实践（总分） | 0.382*** (5.86) | — |
| 迭代交付 | — | 0.142** (2.28) |
| 持续反馈 | — | 0.286*** (4.12) |
| 跨职能协作 | — | 0.168*** (2.86) |
| 自组织管理 | — | 0.126** (2.06) |
| 企业规模 | 0.042 (0.86) | 0.038 (0.78) |
| 敏捷经验 | 0.086** (2.12) | 0.072* (1.82) |
| 团队规模 | -0.028 (-0.62) | -0.032 (-0.72) |
| R² (Level 2) | 0.218 | 0.268 |

注：***p<0.001, **p<0.01, *p<0.05，括号内为t值。

敏捷实践总分对项目绩效的效应为0.382（t=5.86, p<0.001），支持H1。分维度分析显示，持续反馈的效果最强（γ=0.286），跨职能协作次之（γ=0.168），迭代交付（γ=0.142）和自组织管理（γ=0.126）的效果相对较弱但仍显著，支持H1a-H1d。

### 4.2.3 中介效应检验（H2）

| 路径 | 系数 | t值 |
|------|------|-----|
| AP → TPS | 0.468*** | 7.28 |
| TPS → PP（控制AP） | 0.286*** | 4.12 |
| AP → PP（控制TPS） | 0.248*** | 3.68 |

间接效应 = 0.468 × 0.286 = 0.134。Monte Carlo 95%置信区间[0.078, 0.198]，不包含0。中介效应占总效应的比例为0.134/0.382 = 35.1%，属于部分中介，支持H2。

### 4.2.4 调节效应检验（H3）

| 变量 | 系数 | t值 |
|------|------|-----|
| AP → TPS | 0.426*** | 6.42 |
| OAS → TPS | 0.218*** | 3.28 |
| AP × OAS → TPS | 0.182** | 2.86 |

交互项系数为0.182（t=2.86, p<0.01），支持H3。简单斜率分析：高组织支持组（+1SD），AP对TPS的效应为0.608（p<0.001）；低组织支持组（-1SD），效应为0.244（p<0.05）。组织支持不足时，敏捷实践对心理安全感的提升效果减弱约60%。

### 4.2.5 项目复杂度的调节效应（H4）

| 变量 | 系数 | t值 |
|------|------|-----|
| AP → PP（直接） | 0.262*** | 3.86 |
| AP × PC → PP | -0.148** | -2.32 |

交互项系数为-0.148（t=-2.32, p<0.05），支持H4。简单斜率分析：低复杂度组（-1SD），AP对PP的直接效应为0.410（p<0.001）；高复杂度组（+1SD），直接效应为0.114（p=0.186, n.s.）。在高复杂度项目中，敏捷实践对绩效的直接效应不显著，主要通过心理安全感的中介路径发挥作用。

## 4.3 客观绩效验证

以项目管理系统的客观指标验证主观绩效结果：

| 客观指标 | AP系数 | t值 |
|----------|--------|-----|
| 迭代速率（Velocity） | 0.312*** | 4.28 |
| 缺陷密度（反向） | -0.268*** | -3.62 |
| 按时交付率 | 0.228*** | 3.18 |

客观绩效指标的结果与主观绩效一致，增强了研究结论的可信度。

# 第5章 补充研究

## 5.1 敏捷成熟度的非线性效应

采用Sidky等（2007）的敏捷成熟度模型（5级），将216个团队按成熟度分组：

| 成熟度等级 | 团队数 | 项目绩效均值 | 与前一级差异 |
|-----------|--------|------------|------------|
| 1级（初始） | 32 | 3.86 | — |
| 2级（探索） | 48 | 3.72 | -0.14 |
| 3级（适应） | 62 | 4.28 | +0.56*** |
| 4级（成熟） | 46 | 5.12 | +0.84*** |
| 5级（优化） | 28 | 5.48 | +0.36** |

从1级到2级，绩效略有下降（-0.14），这就是"敏捷转型阵痛期"——团队正在学习新方法，旧的工作模式被打破但新模式尚未建立。从2级到4级，绩效快速提升，特别是3级到4级的提升最为显著（+0.84）。从4级到5级，提升幅度放缓，表明边际效益递减。

多项式回归分析证实了S型曲线关系：线性项系数为0.286（p<0.001），二次项系数为-0.042（p=0.128），三次项系数为0.018（p<0.05），支持S型曲线假设。

## 5.2 敏捷实践的交互效应

检验四个敏捷维度之间的交互效应：

| 交互项 | 系数 | t值 |
|--------|------|-----|
| 持续反馈 × 自组织管理 | 0.128** | 2.18 |
| 跨职能协作 × 持续反馈 | 0.096* | 1.72 |
| 迭代交付 × 跨职能协作 | 0.082 | 1.42 |

持续反馈与自组织管理之间存在显著的正向交互效应，表明这两个维度相互增强：自组织团队更能有效利用反馈信息进行自我调整和改进。

## 5.3 团队特征的调节效应

| 调节变量 | AP × 调节变量 → PP | t值 |
|----------|-------------------|-----|
| 团队经验多样性 | 0.112** | 2.08 |
| 团队稳定性 | 0.148** | 2.42 |
| 团队规模（反向） | -0.086* | -1.68 |

团队稳定性和经验多样性正向调节敏捷实践的效果，而团队规模过大则削弱效果。这与敏捷方法强调小团队、稳定团队的理念一致。

# 第6章 讨论与结论

## 6.1 研究发现讨论

本研究系统揭示了敏捷项目管理实践对软件开发项目绩效的影响机制，核心发现可以概括为三个层面。

在实践层面，四个敏捷维度均显著提升项目绩效，但效果存在差异。持续反馈的效果最强，这与敏捷方法"检视与适应"（Inspect and Adapt）的核心理念一致——频繁的反馈循环使团队能够及时发现问题、调整方向，是敏捷方法区别于传统方法的最关键特征。自组织管理的效果相对较弱，可能因为在中国文化背景下，团队自主决策的实践面临更多的组织和文化障碍。

在机制层面，心理安全感的中介作用揭示了敏捷实践影响绩效的"软性路径"。敏捷实践不仅通过改善工作流程直接提升效率，更通过营造安全、信任的团队氛围，激发成员的主动性和创造性。这一发现呼应了Edmondson（1999）关于心理安全感是团队学习和绩效基础的经典论断。

在边界条件层面，组织支持和项目复杂度的调节效应揭示了敏捷实践发挥效果的前提条件。缺乏组织支持时，敏捷实践的效果大幅减弱；高复杂度项目中，敏捷实践更依赖于心理安全感的中介路径。这些发现解释了为什么许多敏捷转型未能达到预期效果——不是敏捷方法本身有问题，而是缺乏必要的组织和团队条件。

## 6.2 理论贡献

第一，本研究将社会技术系统理论引入敏捷项目管理研究，揭示了敏捷实践通过技术系统（工作流程优化）和社会系统（心理安全感提升）双重路径影响项目绩效的机制。

第二，本研究发现了敏捷成熟度与项目绩效之间的S型曲线关系，为理解敏捷转型的阶段性特征提供了理论框架。

第三，本研究采用多层次、多来源的研究设计，结合主客观绩效数据，克服了现有研究中常见的同源偏差和主观偏差问题。

## 6.3 实践启示

第一，软件企业在推进敏捷转型时，应优先建立持续反馈机制，这是投入产出比最高的敏捷实践。

第二，管理层应为敏捷团队提供充分的组织支持，包括授权、资源保障和制度适配，避免"口头敏捷、实际瀑布"的困境。

第三，企业应对敏捷转型的"阵痛期"有合理预期，在成熟度2-3级时绩效可能暂时下降，需要坚持投入而非半途而废。

第四，高复杂度项目应特别关注团队心理安全感的建设，因为此时敏捷实践的效果更依赖于团队氛围。

第五，敏捷团队应保持适度规模（7±2人）和人员稳定性，频繁的人员变动会削弱敏捷实践的效果。

## 6.4 研究局限与展望

第一，横截面设计限制了因果推断，未来研究可采用纵向追踪设计或准自然实验方法。

第二，样本以中国软件企业为主，跨文化比较研究有助于检验结论的普适性。

第三，本研究未区分不同敏捷框架（如Scrum vs. Kanban）的差异化效果，这是未来研究的方向。

第四，人工智能辅助的敏捷项目管理（如AI驱动的需求分析、自动化测试）是值得探索的前沿领域。

## 6.5 结论

本研究基于社会技术系统理论，通过多层次研究设计揭示了敏捷项目管理实践对软件开发项目绩效的影响机制。研究发现，敏捷实践通过提升团队心理安全感间接提升项目绩效，且这一效果受到组织支持和项目复杂度的调节。研究结论为软件企业的敏捷转型提供了理论指导和实践参考。
